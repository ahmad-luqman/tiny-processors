# F1 standalone FP32 hardware contract

F1 builds synthesizable hardware, not a software floating-point library for the
CPU. In F1 the CPU remained RV32I and Berkeley SoftFloat was a test-only
oracle. [F2](rv32-f.md) now integrates this unchanged hardware with the CPU and
uses SoftFloat for emulator arithmetic and a separate software benchmark.

## Request and response

`fp32` has a synchronous active-high `reset`, clock, and one outstanding request.
A request is accepted on a rising edge with `req_valid && req_ready`. Its
`op[4:0]`, `rm[2:0]`, and `a/b/c[31:0]` are sampled on that edge. Operands are raw
IEEE binary32 bits, except integer conversion inputs. The producer must hold a
pending request stable. `req_ready` is low during execution and while a response
is pending; consuming a response makes the unit ready on the following cycle.

`resp_valid`, `result[31:0]`, `flags[4:0]`, and `error` hold until
`resp_ready`. Flags are per operation, ordered NV,DZ,OF,UF,NX (bits 4 through 0).
Reset takes priority over transfers, clears the response, and cancels execution.
No completion from a canceled request may escape reset. `req_ready` is always
meaningful. The response payload (`result`, `flags`,
and `error`) is meaningful only when `resp_valid` is asserted.

| Code | Operation | Computation |
| --- | --- | --- |
| 0 | ADD | a+b |
| 1 | SUB | a-b |
| 2 | MUL | a*b |
| 3 | FMADD | `a*b+c` |
| 4 | FMSUB | `a*b-c` |
| 5 | FNMSUB | `-a*b+c` |
| 6 | FNMADD | `-a*b-c` |
| 7 | DIV | a/b |
| 8 | SQRT | sqrt(a) |
| 9 | I32_TO_F32 | signed integer a → float |
| 10 | U32_TO_F32 | unsigned integer a → float |
| 11 | F32_TO_I32 | float a → signed integer |
| 12 | F32_TO_U32 | float a → unsigned integer |
| 13 | EQ | a==b → 32-bit 0 or 1 |
| 14 | LT | a<b → 32-bit 0 or 1 |
| 15 | LE | a<=b → 32-bit 0 or 1 |
| 16 | MIN | minimum(a,b) |
| 17 | MAX | maximum(a,b) |

| Code | Rounding mode | Meaning |
| --- | --- | --- |
| 0 | RNE | nearest, ties to even |
| 1 | RTZ | toward zero |
| 2 | RDN | toward negative infinity |
| 3 | RUP | toward positive infinity |
| 4 | RMM | nearest, ties away from zero |

| Mask | Flag | Meaning |
| --- | --- | --- |
| 0x01 | NX | inexact |
| 0x02 | UF | underflow |
| 0x04 | OF | overflow |
| 0x08 | DZ | divide by zero |
| 0x10 | NV | invalid operation |

All operations require a legal explicit mode, even comparisons. Other modes
(including dynamic mode 7) or opcodes produce `error=1`, zero result/flags, and
one normal response. F2 resolves dynamic rounding and illegal instructions.

Arithmetic produces canonical NaN `0x7fc00000`. Subnormals are supported without
flush-to-zero. Tininess is detected after rounding. Exact cancellation is −0
only under RDN, except same-sign zero operands preserve that sign. Invalid
operations and signaling NaNs set NV. FMA rounds once, including when its
unrounded product is outside the binary32 range. Zero×infinity sets NV even
when the addend is a quiet NaN.

Comparisons follow RISC-V F: equality is quiet except for signaling NaNs;
ordered comparisons raise NV on any NaN. Minimum/maximum return the numeric
operand for one NaN, canonical NaN for two, and raise NV only for signaling
NaNs. Minimum of opposite zeros is −0; maximum is +0.

Integer conversions round before range checking. Invalid conversions saturate
as required by F: signed negative overflow to INT_MIN, signed positive overflow
and NaN to INT_MAX; unsigned negative overflow to zero, positive overflow and
NaN to UINT_MAX. Invalid conversions set NV, not NX. Representable conversions
set NX when inexact. Sign operations, classification, moves, floating register
state, accrued flags, instruction decode, and memory operations belong to F2.

## Hardware approach

Use a single multicycle controller and common round/pack path. Add/subtract,
multiply and FMA work as a conventional FPU does: they place the larger operand
in an 80-bit window, shift the other right by the exponent difference with a
sticky bit, add, then normalize with a leading-zero count and a barrel shift.
Multiplication computes the full 24×24 product; FMA retains it until addition
and final rounding, so it still rounds once. Division uses restoring quotient
generation; square root uses radix-2 digit recurrence. Both retain a remainder
for sticky rounding. No Verilog `real`, host floating arithmetic, opaque
hardware core, or synthesizable division operator is used.

Until 2026-10-03 a 576-bit serial accumulator did this instead; [the narrow
datapath](#narrow-datapath-2026-10-03) records the replacement.

All requests must complete within 2048 execution cycles, excluding response
backpressure. There is no throughput or fixed-latency promise in F1.

## Independent reference

Pin Berkeley SoftFloat to `a0c6494cdc11865811dec815d5c0049fba9d82a8`, using
its RISCV specialization, all five modes and tininess after rounding. Reset
oracle exception flags for every operation. Minimum/maximum use an adapter because SoftFloat has no public min/max operation.
SoftFloat supplies the numeric comparison; literal expected results check the
adapter’s RISC-V NaN/zero rules. No RTL
arithmetic code is shared with the oracle. Source/license provenance accompanies
the vendored files. Hand-computed anchors also check the oracle's integration.

## Build and verification

Prerequisites are the existing Icarus, Verilator, Yosys, Python 3.10+ and a
C11 host compiler (`HOST_CC`, default `cc`). No Python packages, RISC-V compiler,
SDL, network access or software floating-point firmware are needed for F1.
The vendored oracle uses compiler 128-bit integer support (Apple Clang works).
Its sources remain byte-for-byte upstream, including upstream whitespace;
`third_party/softfloat/SHA256SUMS.json` pins each source file. Every arithmetic
runner invocation, including waves and benchmarks, verifies both those hashes
and the complete file inventory before using the oracle. `--check-reference`
performs that check alone. Compiler warnings remain errors for our wrapper;
upstream sources retain warnings without `-Werror`.

```sh
make test-fp32             # Oracle/harness tests, Icarus vectors and protocol
make test-fp32-verilator   # Same tools, arithmetic and protocol through Verilator
make lint-fp32 synth-fp32  # Strict RTL lint, generic gates and latch rejection
make waves-fp32            # build/fp32/arithmetic.vcd and protocol.vcd
make bench-fp32            # Per-operation latency for the literal anchor set
make stress-fp32           # Seeds 424242, 7, 99 and 31337 on Verilator (~3.1 M requests)
# One stress seed by hand, after building the Verilator simulator:
python3 tools/fp32_vectors.py --simulator build/verilator-fp32/fp32_sim \
  --work build/fp32/stress --seed 424242 --random 2000 --cancellation 1000
```

`FP32_SEED`, `FP32_RANDOM` and `FP32_CANCELLATION` override the Make targets'
seed, per-operation, per-rounding-mode random count, and FMA cancellation count.
The Python runner also accepts `--ops`, `--anchors-only` and `--wave`. Every run
prints each operation's latency range and fails if one exceeds the bound in the
latency table below (`LATENCY_BOUNDS` in the runner). Generated requests
and exact expected responses remain in `build/fp32/`; a mismatch saves its
single transaction as `failure-SEED.txt` alongside the complete sequence.
Keep the same source revision and `--ops` list/order when reproducing a seed:
changing the list changes the random stream. A successful run removes the
failure file for its seed in that work directory. Use separate work directories
for subsets; waves use `build/fp32/waves/` and never replace the full-test vectors.
An isolated transaction diagnoses arithmetic; retain the full sequence when
investigating a state-dependent failure. Empty/malformed vectors, incorrect
reference record counts, missing tools, silent simulator success and timeouts
fail rather than skip verification. Oracle failures and timeouts include their
captured diagnostics. Both simulator targets run the same harness rejection
tests, including result-only, flags-only and error-only mismatches.

The RTL vector file has eight whitespace-separated fields per newline-terminated
line: decimal op/mode, hexadecimal a/b/c/result/flags, and decimal error.
Op is at most two decimal digits; mode/error one; operands/result at most eight
hex digits; flags at most two. Characters and widths are checked before numeric
conversion; x/z, extra fields, and overlong lines are rejected without truncation.

The corpus combines cross-products of exceptional/boundary operands, all five
rounding modes, seeded unrestricted bits mixed with those edges, and products
with addends chosen within two ULPs of cancellation. Literal anchors test FMA
without intermediate overflow, FMA's distinction from multiply-then-add, invalid
zero×infinity with a NaN addend, integer saturation, quiet/signaling comparisons,
min/max NaN and zero rules, ties, and the normal/subnormal rounding boundary.
Protocol tests modify source operands after acceptance, stall responses with a
second request waiting, consume consecutive operations, and verify that reset
cancels work without a later completion. The queued request computes 1+2 after
sqrt(4), so a replay of the previous result is distinguishable. State coverage
is sampled after reaching the reset assertion edge and is sized from the shared
RTL state definitions; the expected check count and a PASS record are required.
These are reproducible tests, not an exhaustive proof of every operand combination.

Claude’s review exposed a test defect in the initial acceptance record: reset
coverage was sampled before waiting for a negedge, which counted DECODE even
though reset occurred in ALIGN. Moving the sample alone reproduced the failure
(`reset_states=ffd`). The corrected driver now asserts reset during DECODE at
20,880 ns. Inspection of the regenerated VCD confirms actual reset assertions
in states 0–11 and all six selected divide/square-root iterations.

## From bits to gates

A finite binary32 value is `(-1)^sign × significand × 2^(effective_exp−150)`.
The significand is the 23 fraction bits with an implicit leading one for normal
numbers, or a leading zero for subnormals. `effective_exp` is the encoded
exponent except that zero becomes one. `unpack` shifts a subnormal significand
left until its leading one reaches bit 23, lowering the exponent to match, so
every nonzero operand arrives as `1.fff… × 2^e`. Multiplying two of them gives
a 48-bit product whose bit 46 weighs `2^(ea+eb)`.

Add/subtract, multiply and FMA share one path. Each addition operand becomes a
48-bit magnitude whose bit 47 weighs `2^e`: a significand `s` loads as `s<<24`
with its unbiased exponent, and the product is normalized by at most one bit so
its leading one is also bit 47. A plain multiply adds zero. Subnormal inputs are
normalized on unpack, so every nonzero magnitude has its leading one at bit 47.

Both operands load at bits 78..31 of an 80-bit window, leaving bit 79 for a
carry. The one with the larger exponent goes to `addend` and sets the window's
exponent; the other goes to `magnitude` with its sign, and `ALIGN` shifts it
right by the exponent gap in one cycle, ORing every bit shifted out into bit 0
(the sticky "jam"). A zero operand never leads. `COMBINE` chooses addition or
magnitude subtraction by sign and leaves the sum in `magnitude`. `NORMALIZE` counts leading zeros, shifts the
leading one to bit 79 and lowers the exponent by the count in one cycle.
`DENORMALIZE` shifts right with the same jam when the exponent is below −126.
Finally `ROUND` examines the top 24 bits, the next guard bit, and the OR of all
remaining bits. Mode, sign, guard, sticky and the retained low bit choose
whether to increment. Carry can increase the exponent; exponent overflow selects
infinity or the largest finite value.

Why the 80-bit window loses nothing that matters, stated in the window as
`COMBINE` leaves it: a gap of at most 31 keeps the shifted operand's 48 bits
whole, so the sum is exact. A gap of 32 or more pushes bits off the bottom, but
then the leading operand is at least 2^78 and the other below 2^47, so the sum or
difference keeps its leading one at bit 77 or above and `NORMALIZE` shifts it
left by at most two. The rounding guard bit therefore sits at bit 53 or above,
with every lower bit feeding sticky. The leading operand's bits 30..0 are zero,
so it is even, and the jammed operand is odd; the computed sum is odd and the
exact sum lies within one of it. The two agree in every bit above bit 0 and both
have a nonzero bit below the guard, so they round alike and both raise inexact.
This is the guard/round/sticky argument every FPU relies on; FMA's cancellation
case (gap 0 or 1) is always in the exact range. For the same reason
`magnitude == addend` in `COMBINE` happens only for an exact cancellation, so
the sign rule for an exact zero never fires on an inexact result.

Tininess after rounding is evaluated at binary32 precision with an unbounded
exponent, before subnormal quantization. It is **not** just a test of the final
encoded exponent. For example, `00800000 × 3f7fffff` under RNE returns
`00800000` with **UF|NX**, despite encoding a normal result. The initial
implementation missed UF here; the independent oracle exposed it and this is
now a literal regression anchor. Exact subnormal results do not raise UF.

Division normalizes two 24-bit significands, then uses a compare/subtract and
left shift for each of 27 quotient bits. A nonzero remainder supplies sticky.
Square root consumes two radicand bits per cycle, compares the remainder with
`(partial_root << 2) | 1`, conditionally subtracts, and appends one root bit.
After 27 steps it too has guard precision and an exact nonzero-remainder test.
Both use the common normalization and round/pack path. Integer conversions use
the same rounding decision with a 33-bit rounded magnitude before range checks.

The declarations become physical hardware: the two 80-bit registers account
for 160 stored bits; operand latches, signs, the alignment shift, recurrence
registers, response registers and FSM add storage. `ALIGN`, `DENORMALIZE` and
`INT_SHIFT` share one jam shifter on `magnitude` (seven levels of 2:1 muxes over
80 bits, as the shift amount has seven bits); normalization's left shift is a
second barrel shifter, driven by a priority encoder that counts leading zeros. The 24×24 product becomes combinational multiplier
logic; wide addition, subtraction and rounding become adders, comparators and OR
trees. Yosys maps/merges some registers and recodes the controller, so final
flip-flop counts need not equal a sum of every declared `reg` width.

| Operation family | Observed request-to-response cycles in stress corpus |
| --- | --- |
| Add/subtract | 1–8 |
| Multiply | 1–8 |
| Fused variants | 1–8 |
| Divide | 1–33 |
| Square root | 1–31 |
| Integer to float | 1–5 |
| Float to integer | 1–3 |
| Comparisons, min/max, rejected request | 1 |

Counts exclude response backpressure; the one-cycle cases bypass arithmetic
for special values. The contract bound is 2,048 cycles, and the vector runner
fails any run that exceeds these ranges. Each shift takes one cycle: `ALIGN` and
`INT_SHIFT` are one visit, while `NORMALIZE` and `DENORMALIZE` spend a second
cycle confirming the leading one or the exponent before moving on. These are RTL
cycles and generic cell counts, not host performance, physical timing closure,
or a silicon clock-frequency estimate. A commercial FPU pipelines these same
steps so that a new add or multiply can start every cycle with a latency of
three to five; this unit runs them one after another for one request at a time.

## Narrow datapath (2026-10-03)

The 576-bit serial accumulator made add and multiply cost about 550 cycles
whatever the operands' exponent gap, because each operand shifted from the fixed
2^-298 origin to its own exponent. Hard-float programs paid for it: the
Mandelbrot showcase needed coarse blocks to fit a Verilator run. The unit now
aligns to the larger exponent and normalizes with a leading-zero count, as
described above. The port, operation table, states, flags and results are
unchanged; only latency and area moved, and float-to-integer conversion lost a
cycle when `INT_SHIFT` became a single visit.

| Measurement | 576-bit serial | 80-bit window |
| --- | ---: | ---: |
| Literal anchors (original 47): add / multiply / FMA, worst case | 558 / 582 / 604 | 7 / 8 / 7 |
| Stress corpus seed 424242, worst add, multiply or FMA | 902 | 8 |
| Stress corpus seed 424242, total cycles | 52,160,538 (259,407 requests) | 1,354,144 (259,411) |
| Yosys 0.69 generic cells / flip-flops (`make synth-fp32`) | 25,685 / 1,530 | 12,424 / 493 |
| `floatcheck` / `floatconvert` FPU issue/wait cycles | 5,081 / 89 | 179 / 23 |

The first version of the window gave each operand its own alignment shifter and
synthesized to 14,362 cells. Loading the trailing operand into `magnitude`, so
that `ALIGN`, `DENORMALIZE` and `INT_SHIFT` share one shifter, removed about
1,900 cells without changing a result or an addition's cycle count.

Exactness was checked against the same pinned SoftFloat oracle, on Verilator
and Icarus for the default corpus (70,411 requests, including four anchors
where the jammed bit alone decides a round-to-nearest-even tie) and on Verilator
for `make stress-fp32`: seeds 424242, 7 and 99 with 259,411 requests each
(20,000 of them FMA cancellation requests), and seed 31337 with 20,000 random
triples per operation and mode plus 20,000 cancellation requests (2,259,411).
All gave exact result, flag and error agreement within the latency bounds. The
protocol checks pass on both simulators with reset reached in all 12 states.
Simulation-only checks (`ifndef SYNTHESIS`) stop the run if an addition operand
is ever loaded off bits 78..31 or `INT_SHIFT` sees an exponent above 31.

## Three waveform observations and exercises

Open the two VCD files from `make waves-fp32` in the same viewer used by the
other labs. Times below are nanoseconds; VCD storage uses picoseconds.

1. **Fused cancellation:** in `arithmetic.vcd`, anchor index 9 (zero-based) starts at 1,165 ns.
   At 1,185 ns the controller is in `COMBINE`; its result is registered at
   1,195 ns as the controller enters `NORMALIZE`, retaining the low product
   bits. One leading-zero shift ends normalization
   at 1,215 ns with exponent −46; the response at 1,235 ns is `a8800000`
   (−2^-46), flags zero. The operands are `(1+2^-23) × (1−2^-23) − 1`.
   Predict the result if multiplication had rounded first, then compare it
   with the actual `magnitude` and `addend` signals.
2. **Remainder and rounding:** anchor index 17 (zero-based) is `1/3`. `DIVIDE` runs from 2,025
   to 2,295 ns, producing 27 quotient bits and a nonzero remainder. At 2,335
   ns the result is `3eaaaaab` with NX. Change the rounding mode to RTZ in a
   copied request and predict the last result bit before rerunning the oracle.
3. **Cancel on the final iteration:** in `protocol.vcd`, reset is asserted at
   250,920 ns while `state=DIVIDE`, `iteration=1`. Reset suppresses a pending
   interface transfer and the next rising edge discards that quotient.
   The next request computes `1/3` successfully; no old response may appear.
   Follow `reset`, `state`, `iteration`, `req_ready` and `resp_valid`, then
   compare with the held-response reset at 229,790 ns.

## F2 handoff (completed)

The standalone port and operation table remain the integration boundary.
[F2](rv32-f.md) adds floating registers, complete F decode, floating CSRs/Zicsr,
accrued flags, dynamic rounding, reset-safe writeback and matching emulator
execution. Its compiled C examples retain ILP32 and exercise runtime inputs.
The existing CPU, emulator, MMIO and integer firmware were unchanged by F1;
F2 preserves their integer behavior while adding the floating architecture.
