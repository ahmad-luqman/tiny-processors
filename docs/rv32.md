# RV32 machine: contract and first firmware

This document fixes the machine contract for our RISC-V computer and describes the first firmware image built against it. It is our own small machine, not a Linux-capable platform and not a copy of QEMU's `virt` board: three addresses were chosen to coincide with `virt` so QEMU can serve as an independent reference runner, nothing else is borrowed. SAP8 remains the separate teaching CPU.

Primary sources: the [RV32I chapter](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html) of the RISC-V unprivileged specification (RV32I version 2.1) and the [RISC-V ELF psABI](https://github.com/riscv-non-isa/riscv-elf-psabi-doc) (integer calling convention, `e_flags`).

## Implementation plan (M1)

1. Record actual tool paths and versions; read the ISA chapter and psABI before fixing the contract.
2. Write the contract below: reset, byte order, address map, memory transactions, alignment and faults, supported ISA, and the console/done protocol.
3. Complete the cross toolchain: Homebrew Clang 22 compiles RV32I, Homebrew lld links it, QEMU runs it.
4. Add startup assembly, a linker script, the multiply/divide runtime, and a C self-check with hand-computed expected values.
5. Execute the image on QEMU and require the console line and exit status to agree.
6. Add build/validation commands without touching the default counter target; write the [C-to-instructions walkthrough](c-to-instructions.md).

All six steps are complete; see [Milestone result](#milestone-result).

## Supported ISA and privilege

- RV32I version 2.1: 32 registers with `x0` hardwired to zero, 32-bit instructions only. No M, A, F, D, or C extensions. Multiplication and division are runtime routines.
- ILP32 soft-float C ABI: `int`, `long`, and pointers are 4 bytes; arguments in `a0`–`a7`, results in `a0`/`a1`; `s0`–`s11` callee-saved; `sp` 16-byte aligned at every call; integers narrower than 32 bits are widened according to their own signedness.
- Little-endian memory. `FENCE` completes with no effect: one hart, no caches.
- Planned machine: machine mode only. `ECALL`, `EBREAK`, illegal instructions, misaligned accesses, and accesses outside the map trap through `mtvec` with `mcause`/`mepc`/`mtval`; interrupts are later work. The emulator (M2) implements this trap contract first.
- M1 slice: no CSR instructions are used or required. There is no trap handler; a trap on the reference runner vectors to the reset value of `mtvec`, address 0, which has no memory, so the run hangs and the driver reports a timeout. This is a recorded limitation, not an accepted behavior.

## Reset

At reset the PC is `0x8000_0000`. Every other register is unspecified, so firmware must not read one before writing it. Memory holds the firmware image at its link addresses; other RAM contents are unspecified and `.bss` is zeroed by startup code.

QEMU reconciliation: `qemu-system-riscv32 -M virt -cpu rv32i -bios none -kernel image.elf` runs a mask ROM at `0x1000` that loads `a1` with a device-tree pointer, would load `a0` with the hart id (a `csrr`, executed as `nop` on the CSR-less `rv32i` model), and jumps to the DRAM base `0x8000_0000`. This was verified with `-d in_asm`. Our image therefore does not rely on the ELF loader honoring `e_entry`: the build asserts `e_entry == _start == lowest load address == 0x8000_0000`, and `_start` is the first instruction of the image.

## Memory map

| Region | Base | Size | Planned machine | M1 slice |
| --- | --- | --- | --- | --- |
| Done register | `0x0010_0000` | 4 bytes | A word write ends the run | Same |
| Console | `0x1000_0000` | 8 bytes | TX byte at +0, status at +5 | Same |
| RAM | `0x8000_0000` | 4 MiB | Code, data, stack, later framebuffer and shared buffers | Only the first 256 KiB: image and `.bss` from `0x8000_0000`; stack `0x8003_C000`–`0x8004_0000` |
| Everything else | — | — | Access fault | Unspecified; QEMU `virt` has other devices there that our firmware never touches |

QEMU runs with `-m 4M` so its RAM bound equals the contract. QEMU stores its device tree near the top of that RAM (2 MiB aligned below the end); firmware ignores it and the 256 KiB slice never reaches it. Timer, input, and framebuffer addresses are chosen in M5; after M2 our own emulator is the primary runner, and QEMU compatibility is a goal only for the three addresses above.

## Memory transaction contract

For the RTL machine (M3 onward), one ready/valid port per CPU with `addr[31:0]`, `we`, `wstrb[3:0]`, `wdata[31:0]`, `rdata[31:0]`, and `error`. A request is presented with `valid` and held stable, including all fields, until the slave asserts `ready` in the same cycle. One request is outstanding at a time. A write takes effect exactly once, at acceptance. Reads return the full aligned word; the CPU selects and sign- or zero-extends bytes and halfwords. `error` set at acceptance means the access is outside the map or otherwise refused, and the CPU raises the access-fault trap. Devices may hold `ready` low for any number of cycles.

## Alignment and faults

Only naturally aligned accesses are defined: `lw`/`sw` on 4-byte boundaries, `lh`/`lhu`/`sh` on 2-byte boundaries. Instruction fetch is always 4-byte aligned because there are no compressed instructions. Misaligned data accesses trap in the planned machine; the M1 firmware never performs one. After the done register is written nothing further executes; the startup code spins afterwards only as a guard.

## Devices

### Console at `0x1000_0000`

| Offset | Access | Meaning |
| --- | --- | --- |
| +0 | Write byte | Transmit the byte |
| +5 | Read byte | Bit 5 (`0x20`) set when a byte can be accepted; other bits read 0 |

In our machine the ready bit is always 1 and every byte is accepted immediately. Firmware still polls it before each store so the same image behaves on a real UART: on QEMU this is the 16550's transmit-holding and line-status registers, which never block here either. Reads from +0 and every other offset are undefined. Output is bytes; the firmware chooses the text.

### Done register at `0x0010_0000`

| Word written | Meaning | QEMU exit status |
| --- | --- | --- |
| `0x0000_5555` | Pass | 0 |
| `(code << 16) \| 0x3333`, code 1..255 | Fail with `code` | `code` |
| `0x0000_7777` | Reserved: QEMU resets the machine; never write it (we run with `-no-reboot`) | — |
| Anything else, or byte/halfword writes | Undefined | — |

Codes are limited to 1..255 because process exit statuses are eight bits; a larger code would be truncated and code 0 would be indistinguishable from pass. The M1 firmware prints exactly one console line before the write: `PASS <8 hex digits>` or `FAIL <code>`. The driver requires the line and the exit status to agree.

## Firmware image and ABI

The image is an ELF32 little-endian executable: `e_machine` 243 (RISC-V), `e_type` `ET_EXEC`, `e_flags` 0 (no compressed instructions, soft-float ABI), `Tag_RISCV_arch` `rv32i2p1`. One `PT_LOAD` segment starts at `0x8000_0000` with load address equal to run address, so startup copies nothing. Section order and symbols come from [link.ld](../programs/rv32/link.ld):

| Section or symbol | Meaning |
| --- | --- |
| `.text` | Code; `.text.init` from [start.S](../programs/rv32/start.S) is kept first so `_start` is at `0x8000_0000` |
| `.rodata` | Constants and string literals |
| `.data`, `__data_start`, `__data_end` | Initialized globals, already in place when loaded |
| `.bss`, `__bss_start`, `__bss_end` | Zero-initialized globals, word aligned, zeroed by `_start` |
| `_end` | First free byte after `.bss` |
| `_stack_bottom`, `_stack_top` | 16 KiB stack at the top of the 256 KiB slice; `_stack_top` is 16-byte aligned |

Startup sets `sp`, zeroes `.bss` one word at a time, calls `main`, then falls into `rv32_exit`, which converts `main`'s return value (0 pass, 1..255 fail) into the done word. No global pointer is set up because linker relaxation is disabled; no thread pointer or heap exists.

Compiler and linker flags, from the [Makefile](../Makefile):

| Flag | Reason |
| --- | --- |
| `--target=riscv32-unknown-elf -march=rv32i -mabi=ilp32` | Base ISA only; soft-float ILP32 objects |
| `-mcmodel=medlow` | Absolute `lui`/`addi` addressing; on RV32 it spans the whole address space, so `0x8000_0000` is fine and linked addresses are visible in listings |
| `-mno-relax` | The linker leaves instruction sequences as compiled, so object and linked listings match line for line; enabling relaxation is an exercise |
| `-ffreestanding -fno-builtin -nostdlib -static` | No hosted C library, no implicit calls except the arithmetic libcalls we supply |
| `-O2 -g` | Real code generation with source interleaved in the listing |
| `-fno-asynchronous-unwind-tables -fno-unwind-tables` | No `.eh_frame`; the image checker rejects unexpected allocated sections |
| `--ld-path=/opt/homebrew/opt/lld/bin/ld.lld` | Explicit linker; `-fuse-ld=lld` would search the compiler's own directory and then `PATH` |

### Runtime routines

Clang lowers 32-bit `*`, `/`, and `%` on an RV32I target to calls named `__mulsi3`, `__divsi3`, `__udivsi3`, `__modsi3`, and `__umodsi3`. Homebrew's LLVM ships no compiler-rt for RISC-V, so [muldiv.c](../programs/rv32/rt/muldiv.c) provides them as aliases of `rv32_mul`, `rv32_div`, `rv32_divu`, `rv32_rem`, and `rv32_remu`. Results follow the RISC-V M extension exactly: division by zero yields all ones (`-1`) with the dividend as remainder; `INT32_MIN / -1` yields `INT32_MIN` with remainder 0; signed quotients truncate toward zero. Future `MUL`/`DIV`/`REM` hardware must agree with these routines. The same file compiles natively so [test_rv32_rt.py](../tests/test_rv32_rt.py) can compare it with Python integers at `-O0` and `-O2`.

The signed routines work on unsigned magnitudes and fix up the sign afterwards, so `INT32_MIN` is never negated as a signed value.

### Image outputs and checks

`make firmware-rv32` writes `build/rv32/selfcheck.elf`, `.lst` (disassembly with source), `.bin` (flat image from `0x8000_0000`), `.map`, and `.readelf`. `make check-rv32-image` runs [rv32_image.py](../tools/rv32_image.py), a standard-library ELF32 parser that will become the emulator's loader. It rejects an image unless: class, byte order, machine, type, and `e_flags` match the contract; the entry point, `_start`, and the lowest load address are all `0x8000_0000`; every load segment is word aligned, has equal load/run addresses, and lies inside the 256 KiB slice; `.text`, `.rodata`, `.data`, `.bss` exist and no other allocated section does; the `.bss` symbols match the section; the stack follows `_end` inside RAM with a 16-byte aligned top; no symbol is undefined; the listing contains no undecodable instruction and no `mul*`, `div*`, `rem*`, `csr*`, `c.*`, `fence.i`, `ecall`, `ebreak`, `wfi`, or `*ret`. It also writes `build/rv32/selfcheck.hex`, little-endian 32-bit words from `0x8000_0000` for `$readmemh`, and verifies the `.bin` written by `llvm-objcopy` equals its own flattening byte for byte.

## Build and run

```sh
make toolchain-rv32     # Check tool paths and print clang, lld, and QEMU versions
make firmware-rv32      # ELF, listing, flat binary, map, and readelf dump under build/rv32/
make check-rv32-image   # Contract checks on the ELF and listing; writes selfcheck.hex
make run-rv32-qemu      # Run on QEMU virt; save the console transcript; compare exit status
make test-rv32-tools    # 12 unit tests for the image checker and QEMU driver (no toolchain)
make test-rv32-rt       # Host build of muldiv.c compared with Python at -O0 and -O2
make test-rv32          # All of the above
make disasm-rv32        # Print the listing
```

`make test` remains the counter test and every earlier target is unchanged. Tool locations are Make variables with defaults for Homebrew on Apple Silicon: `RV32_LLVM` (`/opt/homebrew/opt/llvm@22/bin`), `RV32_LD` (`/opt/homebrew/opt/lld/bin/ld.lld`), `QEMU_RV32` (`qemu-system-riscv32`). Install with `brew install llvm@22 lld qemu`; the compiler and linker come from different LLVM releases (22.1.8 and 23.1.1), which is fine for static RISC-V ELF linking. Nothing needs to be on `PATH`.

To run by hand:

```sh
qemu-system-riscv32 -M virt -cpu rv32i -bios none -kernel build/rv32/selfcheck.elf \
  -m 4M -nographic -monitor none -no-reboot; echo "exit status $?"
```

`tools/rv32_run_qemu.py --cpu` accepts alternatives if a future QEMU release stops booting the bare model: `rv32i,zicsr=true`, then `rv32,m=false,a=false,f=false,d=false,c=false`.

## Milestone result

Completed on 2026-09-19. `make test-rv32` passes from a clean `build/`:

- `make test-rv32-tools`: 12 tests. `make test-rv32-rt`: 6 tests covering an edge grid, division by zero, the `INT32_MIN / -1` case, truncation, 33rd-bit divisors, and 2000 seeded random pairs, at both `-O0` and `-O2`.
- `make check-rv32-image`: entry `0x8000_0000`, `e_flags 0`, arch `rv32i2p1`, one RWX load segment, `.text` 3600 / `.rodata` 29 / `.data` 16 / `.bss` 32 bytes, image 3648 bytes (912 words), stack `0x8003_C000`–`0x8004_0000`, `.bin` identical to our own flattening, no forbidden instructions, no undefined symbols.
- `make run-rv32-qemu`: QEMU 11.1.1 boots the image with `-cpu rv32i -m 4M`, all 28 checks pass, the guest prints `PASS 807d9fad`, and QEMU exits with status 0. The same constant is derived independently in `tests/test_rv32_tools.py` from the 28 hand-computed values. The failure path was exercised too: with the signed routines stubbed, the guest printed `FAIL 10` and QEMU exited with status 10.
- Counter, ALU, SAP8, and SIMD4 targets still pass after the Makefile change.

Limitations that remain: no trap handling in the M1 slice, no timer, input, or framebuffer, QEMU is a reference runner rather than our machine, and nothing here says anything about cycle timing. The next milestone, M2, is the headless emulator that loads this same ELF with the image checker's parser and must produce the same console line and done word.
