# G2: programmable 3D

G2 adds a CPU-commanded 3D device: a **programmable vertex stage** running on
four SIMT lanes, followed by a **fixed-function** pipeline that projects,
culls, rasterizes with Gouraud colour and a 16-bit depth test, and writes the
existing 320×240 RGB332 framebuffer. This record is the contract. The RTL,
emulator device and measured results are added to it as they land.

G1 (2D) and SIMD4 are unchanged. Programmable fragment shading is a later
milestone: the shader core only knows about numbered input and output slots,
so a fragment stage can reuse it without changing the ISA.

Status: **contract and software references** (Python oracle
`tools/rv32_g3d_model.py`, guest C `programs/rv32/g3d_ref.c`, demo content
`tools/rv32_g3d_scene.py`, tests `tests/test_rv32_3d.py`). There is no device
yet.

## What is programmable and what is fixed

| Stage | Kind | Where |
| --- | --- | --- |
| Vertex shader: transform, lighting, displacement | programmable, 4 lanes | shader core |
| Near-plane, guard-band and depth-range cull | fixed | projection |
| Perspective divide and viewport map to S12.4 | fixed, exact divider | projection |
| Back-face cull, triangle setup, attribute gradients | fixed, exact divider | setup |
| Coverage, interpolation, dither, depth test, writes | fixed | raster |

One START runs all of it. The CPU fills the device windows while the device is
idle: the program, a constant bank, the vertex inputs and the triangle list.
The device then shades every vertex, projects them, and draws the triangles in
list order.

## Registers and windows

The non-executable 8 KiB window at `0x20008000` takes aligned word accesses
only.

| Offset | Access | Meaning |
| --- | --- | --- |
| 000 | W | COMMAND: 1 START, 2 RESET, 3 CLEAR_Z |
| 004 | R | STATUS: IDLE 0, BUSY 1, DONE 2, FAULT 4 (whole values, as in G1) |
| 008 | R | ERROR (table below) |
| 00c | R | FAULT_PC: shader PC in bits 6..0, batch number in bits 15..8 |
| 010 | R | CYCLES, busy device ticks |
| 014 | R | STALLS, ticks waiting for memory acceptance |
| 018 | R | INSTRUCTIONS executed by the shader, summed over batches |
| 01c | R | TRANSFERS, accepted Z and framebuffer accesses |
| 020 | R | DIVIDES performed by the fixed-function divider |
| 024 | R | PIXELS written (depth test passed) |
| 028 | R | ZFAIL, covered pixels that failed the depth test |
| 02c | R | CULLED triangles (vertex cull, back face or zero area) |
| 040 | RW | VCOUNT, 1..32 vertices |
| 044 | RW | TCOUNT, 0..64 triangles |
| 048 | RW | ZBASE, the depth buffer's byte address |
| 04c | RW | LIMIT, 1..65535 shader instructions per batch |
| 400–47c | RW | 32 constant words |
| 800–9fc | RW | 128 program words |
| 1000–13fc | RW | vertex inputs: vertex v slot s at `0x1000 + 32v + 4s` |
| 1800–18fc | RW | triangles: word t packs indices `i0 | i1<<8 | i2<<16`; the top byte is ignored |

The counters wrap at 32 bits. START clears them and the outcome, validates the
parameters and every triangle index, and only then begins work.

| ERROR | Meaning |
| --- | --- |
| 0 | none |
| 1 | invalid parameter: VCOUNT, TCOUNT, LIMIT, or ZBASE (not word-aligned, or its 153,600 bytes not in RAM) |
| 2 | internal state, unreachable |
| 3 | illegal opcode (28..63) |
| 4 | mask stack overflow (a ninth IF or LOOP) |
| 5 | control mismatch: ELSE/ENDIF without an open IF, ENDLOOP without an open LOOP, BREAK outside a loop, END inside a block |
| 6 | instruction limit reached in one batch |
| 7 | PC reached 128 |
| 8 | triangle index ≥ VCOUNT |

Errors 1 and 8 are found before any shader work. Errors 3–7 stop the shader
before projection. **No fault happens after the first memory transfer**, so a
faulted job never leaves a partial frame.

## Shader core

Each lane has sixteen 32-bit registers, all zero at the start of every batch,
and a one-bit predicate. The four lanes share the PC, the mask stack and the
batch's instruction count. Vertex `4b + lane` runs in batch `b`. In the last
batch, lanes past VCOUNT start inactive, so a partial batch can never fetch
through a disabled lane's state. (tiny-gpu takes its PC from the last lane,
which a partial block disables. That bug is still open upstream.)

### Encoding

A word is `op[31:26] rd[25:22] ra[21:18] rb[17:14] rc[13:10]`, with `imm[13:0]`
overlapping `rc`. Unused fields are ignored. Numbers are Q16.16 unless the
table says raw.

| Op | Code | Effect on each active lane |
| --- | --- | --- |
| END | 00 | batch done; faults if the stack is not empty |
| LDI rd, v | 01 | rd = sign-extended `word[21:0]` (raw; the assembler takes `1.5f`) |
| LDC rd, k | 02 | rd = constant `imm[4:0]` |
| IN rd, s | 03 | rd = this vertex's input slot `imm[2:0]` |
| OUT s, ra | 04 | output slot `imm[2:0]` = ra |
| SPC rd, sel | 05 | rd = lane, vertex id, VCOUNT, or 0 for `imm[1:0]` = 0..3 (raw) |
| MOV rd, ra | 06 | rd = ra |
| ADD / SUB | 07 / 08 | rd = ra ± rb, wrapping |
| MUL rd, ra, rb | 09 | rd = bits 47..16 of the exact 64-bit product (floor) |
| MAD rd, ra, rb, rc | 0a | rd = rc + MUL(ra, rb), wrapping |
| MIN / MAX | 0b / 0c | signed |
| ABS rd, ra | 0d | wrapping: ABS of −2³¹ is −2³¹ |
| AND / OR / XOR | 0e–10 | bitwise |
| SHL / SRA rd, ra, n | 11 / 12 | shift by `imm[4:0]`; SRA is arithmetic |
| ADDI rd, ra, n | 13 | rd = ra + sign-extended `imm[13:0]` (raw) |
| SLT ra, rb | 14 | predicate = ra < rb, signed |
| SEQ ra, rb | 15 | predicate = ra == rb |
| IF t | 16 | push; mask &= predicate; if no lane is active, jump to t |
| ELSE t | 17 | mask = parent & ~taken; if no lane is active, jump to t |
| ENDIF | 18 | pop; mask = parent |
| LOOP | 19 | push a loop entry |
| ENDLOOP t | 1a | if any lane is active, jump to t; otherwise pop, mask = parent |
| BREAK | 1b | active lanes leave the innermost loop (below) |

Branch targets are absolute PCs in `imm[6:0]`. The assembler resolves them:
IF to its ELSE or ENDIF, ELSE to its ENDIF, and ENDLOOP to the first
instruction of the loop body. A jump lands *on* the ELSE or ENDIF, which then
executes. There is no general branch instruction. Every control transfer is
structured, so reconvergence is exact by construction and needs no
post-dominator analysis.

### The mask stack

The stack has at most 8 entries. Each entry is `(kind, parent, taken)`:
- `kind` is IF or LOOP.
- `parent` is the active mask when the entry was pushed.
- `taken` is, for IF, the lanes that entered the THEN side.

| Event | Stack | Active mask |
| --- | --- | --- |
| batch start | empty | lanes with a vertex |
| IF | push (IF, mask, mask & P) | mask & P |
| ELSE | top must be IF | parent & ~taken |
| ENDIF | top must be IF; pop | parent |
| LOOP | push (LOOP, mask, –) | unchanged |
| ENDLOOP, some lane active | top must be LOOP | unchanged; jump back |
| ENDLOOP, no lane active | top must be LOOP; pop | parent |
| BREAK | clear active lanes from every IF entry above the innermost LOOP | 0 |

Masked-off lanes still spend the cycle: an instruction costs the same whether
one lane or four are active. An IF or ELSE with no active lane skips its body.
Everything else runs with an empty mask until the matching ENDIF or ENDLOOP.

### BREAK

A loop ends when no lane is left active at ENDLOOP, so lanes leave loops only
through BREAK. Suppose BREAK runs two IFs deep inside a loop. Clearing the
active mask alone is not enough: the enclosing IF's ENDIF would restore its
`parent`, which still contains the broken lanes, and they would run the rest
of the loop body again. So BREAK removes the active lanes from the `parent`
of **every IF entry above the innermost LOOP entry**. The LOOP entry keeps
them, so they come back when that loop's ENDLOOP pops it. A BREAK with no LOOP
on the stack is error 5. The AMD R600 control-flow stack (LOOP_BREAK) has the
same rule.

Worked example (`test_break_inside_nested_if_does_not_revive`), lanes 0–3,
where lane 0 breaks inside two IFs on the first iteration:

```text
LOOP                     stack: L(1111)                  mask 1111
  IF   (lanes 0,1)       stack: L(1111) I(1111,0011)     mask 0011
    IF (lane 0)          ... I(0011,0001)                mask 0001
      BREAK              I(1111→1110,0011) I(0011→0010,0001)   mask 0000
    ENDIF                pop → mask = 0010   (lane 0 is not revived)
    ...                  lane 1 counts
  ELSE                   mask = 1110 & ~0011 = 1100
  ENDIF                  pop → mask = 1110
ENDLOOP                  1110 active → loop again; lane 0 returns only when all have left
```

### Faults and the instruction limit

A loop no lane leaves would never end. Instead, a batch that has executed
LIMIT instructions faults with error 6 before its next fetch. FAULT_PC then
holds the PC and batch number of the instruction that was not executed.
INSTRUCTIONS counts instructions that began execution, including a control
instruction that then faulted (stack overflow or mismatch), but not a fetch
refused for the limit, the PC or an illegal opcode. The assembler rejects bad
structure statically. The hardware checks again, because the program window
is raw memory the CPU can fill with anything.

## Fixed function

### Projection and cull

The shader writes clip-space x, y, z, w to output slots 0–3 and colour to
slots 4–6 (Q16.16; the integer part 0..255 is used after clamping). A vertex
is **valid** only when all of these hold:

```text
w ≥ 1/16   and   |x| ≤ 4w   and   |y| ≤ 4w   and   0 ≤ z ≤ w
```

A triangle with any invalid vertex is culled whole. There is no near-plane
clipping. Instead, the guard band bounds every screen coordinate, so edge
products fit in 32 bits. A small open GPU (pongsagon's Tiny Tapeout
tinygpu_v2) freezes on off-screen triangles for lack of such a bound, so the
guard band has its own tests. For a valid vertex, with truncating division:

```text
sx = 2560 + (x·2560)/w        S12.4, 16 subpixels per pixel
sy = 1920 − (y·1920)/w        screen y grows downward
zq = (z·65535)/w              16-bit depth
```

That is 3 divides per valid vertex.

### Setup

The screen area is `(x1−x0)(y2−y0) − (y1−y0)(x2−x0)`. A triangle that is
counter-clockwise in clip space (y up) has **negative** screen area and is
front-facing. Area ≥ 0 is culled as a back face or a degenerate triangle.
Setup then swaps v1 and v2 so the area is positive, as G1 does. Each of the
four attributes (z, r, g, b) gets a gradient per subpixel in Q16. With
`d1 = a1−a0`, `d2 = a2−a0`, `(ex, ey) = v − v0`:

```text
gx = ((d1·ey2 − d2·ey1) << 16) / area        gy = ((d2·ex1 − d1·ex2) << 16) / area
```

That is 8 divides per drawn triangle. The **divider** computes the truncating
quotient of a signed 64-bit numerator by a positive 32-bit denominator,
saturated to int32. It is exact and specified bit for bit: a restoring
divider that checks for overflow, then runs 32 iterations. A sliver triangle's
huge gradient therefore saturates instead of wrapping, and the clamp below
keeps the result in range.

### Raster

- **Scan box:** pixel columns `floor(min sx/16)..floor(max sx/16)` and rows
  likewise, clipped to the screen. It may be empty. Rows are scanned top to
  bottom, left to right.
- **Coverage:** a pixel centre `(16x+8, 16y+8)` is covered when every edge
  function `(bx−ax)(py−ay) − (by−ay)(px−ax)` is positive. An edge function of
  zero counts only when `dy < 0`, or `dy = 0` and `dx > 0`. This is G1's
  top-left rule on subpixel coordinates, so two triangles sharing an edge
  never both write a pixel.
- **Interpolation:** `a = a0 + ((gx·(px−x0) + gy·(py−y0)) >> 16)` exactly in
  64 bits, then clamped to 0..65535 for z and 0..255 for colour. This is
  **affine (screen-space) Gouraud**, not perspective-correct. Adding `16·gx`
  per pixel in a 64-bit accumulator gives the same values, so the hardware
  steps incrementally while the references evaluate directly.
- **Depth:** read the 16-bit Z at `ZBASE + 2(320y + x)`. The test passes on
  strictly less. On a pass, write Z and the pixel (PIXELS). On a fail, count
  ZFAIL and write nothing. At equal depth, the triangle drawn first keeps the
  pixel.
- **Colour:** an ordered 4×4 Bayer dither, with threshold
  `t = B[y&3][x&3]` ∈ 0..15 and `B = 0 8 2 10 / 12 4 14 6 / 3 11 1 9 / 15 7 13 5`,
  adds `2t` to red and green and `4t` to blue, clamps at 255, and packs
  RGB332: `(r & e0) | (g>>3 & 1c) | b>>6`.

  Without the dither, Gouraud shading is mostly invisible. RGB332 has 8
  levels of red and green, so the diffuse and toon shaders rendered identical
  frames before it was added.

TRANSFERS is one Z read per covered pixel plus a Z write and a pixel write per
pass. CLEAR_Z writes `0xffffffff` to all 38,400 words of the depth buffer.

## Precision

| Stage | Format | Rounding |
| --- | --- | --- |
| Shader registers, constants, inputs, outputs | Q16.16, 32-bit | MUL/MAD floor bits 47..16; ADD wraps |
| Screen position | S12.4 | truncating divide |
| Depth | 16-bit unsigned | truncating divide, clamp after interpolation |
| Colour | 8 bits per channel, then RGB332 | clamp, 4×4 ordered dither, truncate |
| Gradients | Q16 per subpixel, int32 | truncating, saturating divide |

**Integer implementations agree exactly (zero tolerance).** The Python oracle
and the guest C reference are compared bit for bit: framebuffer, Z buffer and
every functional counter. The emulator device and the RTL join that
comparison.

**The formats are justified against doubles.** `render_float` runs the
fixed-function stages in double precision, from the same shader outputs, with
no subpixel snap, truncation or clamp. For the cube at four angles:
- **Diffuse:** 1.8–2.5% of covered pixels differ.
- **Toon:** 0.5–0.9% differ, because it has fewer gradients to round.

Of the differing pixels:
- Almost all are **one quantization level** apart, a dither threshold crossed
  by rounding.
- About **5 per frame** sit on a seam between two faces, where the fixed and
  float pipelines disagree about which face owns the pixel.
- 6–14 per frame are silhouette coverage.

The acceptance test bounds this at **3%** (`Precision` in
`tests/test_rv32_3d.py`). Q16.16 is the narrowest format that keeps these
differences at dither scale without a floating-point lane. The CPU's F
extension is not used: the capstone stays `-march=rv32i`.

## Demo content

`tools/rv32_g3d_scene.py` has three things.

**The cube.** 24 vertices, four per face so each keeps its own normal.

| Input slots | Contents |
| --- | --- |
| 0..2 | position |
| 3 | base colour `0xRRGGBB` (raw) |
| 4..6 | normal |

**The constant bank.**

| Constants | Contents |
| --- | --- |
| c0..c15 | the MVP matrix, row-major |
| c16..c18 | the light direction in *object* space, which the CPU rotates so shaders never transform normals |
| c19 | ambient intensity |
| c20 | the frame number (raw) |

**The shaders.**
- **Diffuse** bends each normal toward its corner (`n + p`), so the four
  corners of a face light differently and the interpolation shows.
- **Toon** picks one of three intensities with nested IF/ELSE, so lanes in a
  batch take different paths.
- **Wobble** pushes each vertex along its normal by a triangle wave of the
  frame and the vertex id. The phase is reduced in a LOOP that every lane
  leaves after a different number of iterations.

## References and inspiration

Nothing was copied. Ideas were read, then re-implemented.
- **adam-maj/tiny-gpu:** SIMT lanes sharing one PC, and read-only
  thread-identity registers (here SPC lane/vid). It has **no license** (GitHub
  reports none, and issue #7 is open), so only ideas are used.
- **BigManRaffa/Clementine** (Apache-2.0): its 2-deep IF/ELSE mask stack
  drops the oldest entry on a third push. This design faults instead
  (error 4).
- **vortexgpgpu/vortex** (Apache-2.0): split/join and IPDOM stacks, and the
  Skybox raster unit's fixed-point edge and depth planes.
- **The AMD R600 ISA, control-flow chapter:** PUSH/ELSE/POP and LOOP_BREAK
  with per-lane active masks, the industrial form of the typed stack above.
- **ssloy/tinyrenderer** (Zlib): edge functions and the depth buffer.
- **pongsagon/tt_um_pongsagon_tinygpu_v2** (Apache-2.0): an iterative divider
  for the perspective divide, and the off-screen hang that motivates the
  guard band.
- **GPL projects (MiSTer PSX/N64 GPUs, FGPU):** consulted for ideas only.
